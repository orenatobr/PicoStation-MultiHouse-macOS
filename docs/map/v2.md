# v2 module, part A (format, validation, loading, SD front ends)

Headers: `core/include/mh/v2format.h` (layout and codecs), `core/include/mh/v2.h`.
Sources: `core/src/v2/v2_format.c v2_util.c v2_validate.c v2_load.c v2_hydrate.c v2_sd.c v2_recode.c`.
Tests: `core/tests/test_v2_format.c test_v2_image.c test_v2_sd.c test_v2_audit.c test_v2_fuzz.c` (`make test-v2`; `v2.deps`,
`v2_stubs.inc` stands in for the platform half of the disk layer with a regular file).
Part B (writer) is appended below by its author. Addresses are virtual addresses in `mh64.exe`.

## On-card layout

See the comment at the top of `v2format.h`. Summary (bytes): header A 0, header B 0xA00 (0xA00 slots,
0x930 used, CRC at 0x92C), Case table 0x1400 (256 x 0x50, "CASE"), Disc table 0x6400 (256 x 0x100, "DISC"),
case art 0x16800 (256 x 0x2800), menu 0x296800 (LBA 0x14B4, up to 93 sectors in 0xA00 slots), PSTCFG2 0x2D0A00,
music 0x2D1400, fixed zone ends at 0x500000. Disc packages start at LBA >= 0x2800, 256-block aligned:
track map +0, cheats +5 (0x2800), reserved +0x19 (0xA00), disc art +0x1E (0x2800), RAW at +0x100,
"PSTRSM1" resume block at +0xFF. Header A also is the MBR (type 0xDA entry, 55AA at 0x1FE) when flag bit 1 is set.

## Findings and deviations

* The SD front ends (`sd_write_image`) invalidate header A first, then B, copy 0x1400..end, compare, clear the
  backup GPT, publish B then A, and re-verify after closing; the header publish is done block 1..4 first, block 0 last.
* `project.reserved_c` is the header generation read at load time; the writer derives the next generation from it.
* `v2_load_source` never checks the menu CRC/SHA-1 on load (only the 0xA00 slot padding); the validator does.
* On a recovered header (both slots invalid) the menu is not read from the card but taken from the embedded menu.
* Unterminated Case/Disc string fields are accepted by the original validator and truncated by `a_copy`; the port
  does the same (decode adds a NUL).
* `verification_issue_text` is duplicated (static in v2_load.c) so that part A does not depend on part B.
* `sd_write_project_direct`: the verify flag only selects the final text; the writer has no quick/full switch.
* Audit of part A (docs/audit/v2-validate-load.md): `Disc.nfiles` of a loaded disc is clamped to 99 (`bin_count` is a
  free byte on the card, `MhDisc.files` has 99 entries). The validator reads 0x930 bytes of each header slot and the
  loader 0xA00 with the padding required zero, so an image with dirty header padding validates but does not load (as
  in the original).

## How a project becomes bytes

All offsets in bytes from the start of the target (card or image). `L` = base LBA of a disc package.

1. **Preflight** (`mh_v2_preflight_serials`): every used Case has 1..5 discs, every disc exists, CUE discs were admitted
   (`verified` or `verified_aux`), verified discs have no padding fault (bit 0x20) and every issue bit was accepted.
2. **Menu**: copy of the embedded menu; with `project.has_menu_defaults` the 64 byte record is validated and patched into it
   (`mh_menu_defaults_patch`), then `mh_menu_validate_blob(.., 0x930)`. Failure: `O arquivo menu\menu.bin e invalido ...`.
3. **Validation + preserved extents**: Case Art (a file of exactly 0x2800 bytes), Disc Art (same), cheat blob <= 0x2800,
   raw source consistency (`v2_raw_blocks == sectors * 5` for kinds 4/5, structure OK for CUE discs), resume marker check
   for discs flagged `MH_DF_KEEP_PACKAGE` that belong to this target (card: same capacity as when written, marker block at
   `L+0xFF` equal to the copy in `d->v2_marker`; image: only the marker), at most 256 discs. A disc with a preserved package
   (`mh_kept_package`) keeps its LBA: its extent `[L, L + 0x100 + sectors*5)` must fit the target and not overlap.
4. **Tables in memory** (the "fixed zone", 0x500000 bytes, zero filled): per used Case slot a 0x50 byte record at `0x1400 + slot*0x50`
   (`CASE`, used, disc count, slot, Case byte 5, name 0x20, serial 0x10, art id = slot or 0xFFFF, disc ids, CRC-32 of 0x4C bytes),
   per disc (global index in Case order) a 0x100 byte record at `0x6400 + idx*0x100` (`DISC`, flags `(d->flags>>6 & 1) | 2`, serial,
   name, `L`, `L`, `L+0x100`, sectors*5, sectors, tracks, BIN count, disc art id, `L+5`, cheat size, `L+0x19`, 0xA00, CRC-32, SHA-1,
   record CRC at 0xFC); new discs get `L` from `mh_v2_extent_allocate` (first fit, 256-block aligned, from block 0x2800);
   Case art at `0x16800 + slot*0x2800`. The package metadata of every disc is built once as a dry run (it fills the cheat size).
5. **Capacity**: `need = max(end of last extent) * 512`, at least 0x500000, must not exceed the capacity ("Os jogos nao cabem ...").
6. **Transaction**: remember the old header (A, else B) if valid; invalidate header A (first 512 bytes zeroed, verified), then B;
   write `PSTWIP1` at block 0 (verified). From here on a card has no valid header A (and `recover_v2_header_from_body` refuses it).
7. **Per disc** (items in Case order; "in place" = RAW slots already at the target, "resumed" = finished earlier this session):
   * not in place, not resumed: clear `MH_DF_KEEP_PACKAGE`, zero blocks `[L+0x32, L+0x100)` (including the marker block), stream
     the sectors (`stream_disc`: each 2352 byte sector into a 0xA00 slot with 208 zero bytes at `L+0x100`, running CRC-32 and
     SHA-1 of the 2352 byte parts; a disc verified at admission must reproduce its CRC/SHA-1),
   * always: rebuild the 0x6400 byte package head (track map `PSTTRK1` at `L`, cheats at `L+5`, Disc art at `L+0x1E`) and write it
     with `mh_io_sync_blocks_verified`, set the record CRC,
   * freshly streamed discs only: flush, read the whole RAW area back (padding zero, CRC, SHA-1), then write the resume
     marker block `PSTRSM1` at `L+0xFF` (stamp, copy of the Disc record, optional `PSTVFY1` + issues/accepted) and remember
     it in the project: `d->v2_slot = phys id`, `v2_card_blocks = capacity`, `v2_pkg_b = L`, `v2_pkg_path = path or ""`,
     `v2_marker`, `MH_DF_KEEP_PACKAGE`.
8. **Commit**: flush; menu sectors into `0x296800 + i*0xA00` (CRC-32 and SHA-1 over the 0x930 byte parts); `PSTCFG2` at
   `0x2D0A00`, the Umbrella music at `0x2D1400` (1..0x22EC00 bytes, always written); header (`PSXRAW`, version 2, flags 3, counts,
   generation, CRCs of the three tables and the menu, menu SHA-1, hybrid MBR with sector count `capacity/512 - 1`) into the 0xA00
   slots at 0 and 0xA00 of the in-memory zone; sync `0x1400..0x500000` (only the 512 byte blocks that differ are rewritten, each
   verified, up to 4 attempts), compare it, publish header B, then header A (`mh_v2_publish_header_slot`), compare `0..0x1400`;
   for an image (non empty path) truncate to `need`. The header A is the last byte written: a failure or a cancel earlier leaves
   the target "uncommitted" (header A invalid, `PSTWIP1` in block 0), never half valid.

Generation counter: `1` for a project that was neither loaded from a card nor from an image (`reserved_c` is initialised to 1),
otherwise `reserved_c + 1` (`reserved_c` = generation read by the loader; 1 if it was 0xFFFFFFFF). The writer does not update
the project: reload after a write.

## Progress texts (the original passed a phase code, dropped here)

`Iniciando gravacao dos discos pendentes` (0 / bytes to write), `Gravando: <disc>` and `Ja gravado: <disc>` (per disc), `Gravando: <bin>` /
`Mantendo disco RAW existente` (per 0x500000 byte chunk, bytes written / bytes to write), `Confirmando gravacao: <disc>` (read-back,
bytes verified so far / bytes to write), `Concluido: <disc>`, `Atualizando tabelas e artes do V2` (0 / 0x500000), `Sincronizando tabelas, menu e artes`,
`Verificando tabelas e artes`, `Finalizando biblioteca do SD` (0 / 1). Analysis pass: `Verificando: <bin>`, `Identificando trackset antes de gravar`.
A callback that cancels (`MhProgress.cancel`) is polled after each report; the message of each cancel point is the original's:
`Operacao cancelada antes de gravar.`, `Gravacao cancelada. Mantenha o Manager aberto para retomar.`, `Gravacao interrompida. O disco atual ficou pendente; ...`,
`Gravacao cancelada. Discos concluidos serao aproveitados ao retomar nesta sessao.`, `Finalizacao cancelada. Reaplique nesta sessao para concluir.`;
cancelling at `Atualizando tabelas e artes do V2` returns false with an empty message (original).

## Findings and deviations

* **Time dependent bytes**: only the 8 byte stamp of each `PSTRSM1` marker (block `L+0xFF`, bytes 8..15) and the CRC-32 at its +0x1FC.
  The original used `QueryPerformanceCounter`; the port uses monotonic nanoseconds unless `MhV2Writer.stamp` is set. With a fixed stamp two writes of
  the same project, or a write and a cancelled-then-resumed write, are byte identical (tested). Nothing else depends on time or on addresses.
* The "full verify" flag (6th argument of `v2_write_handle_direct`) is never read by the original; `sd_write_project_direct` only uses it to pick the final text.
* Disc art is stored at `L+0x1E` (buffer offset 0x3C00) while the Disc record's `extra_lba` says `L+0x19` (0xA00 reserved slot, zero). Both are as in the original.
* `build_package_metadata` requires: tracks numbered 1..n, track 1 a data track starting at sector 0 with no pregap, data tracks MODE1 or MODE2, each
  track beginning (`start - pregap`) strictly after the previous one and not after the disc end (the last track is not checked against the disc end), SBI
  data (`d->sbi_data` or the file `sbi_path`) of 4..0x2E8 bytes starting with `SBI\0`. The analysis pass additionally needs `start >= pregap` for every track.
* The I/O error record (`v1_io`, cleared by `m_memset(&v1_io, 0, 0x50)` at the start of the writer) is `MhIo.err`, cleared at the start. The message of a failure
  is `msg [\r\nDisco N: name] [\r\n<what>. Erro Windows: ...]` when an I/O error was recorded (the disc part only once a disc was reached).
  `result_io_msg(.., GetLastError())` has no equivalent: the code is the recorded I/O error code or 0. "Erro Windows"/"Win32" stay in the texts; the numbers are errno
  (mapped to 2, 5 and 32 for ENOENT, EACCES/EPERM and EBUSY in the "Falha ao abrir ... (Win32 N)" texts).
* The gap before the RAW data is zeroed with plain sequential writes (no I/O record), the rest through `mh_io_*` (errors recorded).
* A V2 disc loaded from a card (kind 4) is read through `/dev/rdisk<N>` (`v2_drive`), the original used `\\.\PhysicalDrive<N>`. Reading it needs the same privileges as reading the card.
* `MhDisc.v2_card_blocks` holds the capacity in BYTES (the original compared it with the byte capacity); `MhProject.reserved_c` is the generation.
* Names are copied with `mh_str_copy` (never cuts a UTF-8 sequence), `a_copy` cut bytes; identical for ASCII.
* Image targets: `OPEN_EXISTING` when the path is the image the project was loaded from or the package path of a preserved disc, otherwise created and truncated; the file is
  extended to `max(5 MiB, size, estimate)` first (sparse), and cut to the final size at the end.

## Ambiguities

* `Case` record byte 7 is copied from `MhCase.pad5` (orig +0x11AD); no code writes it in the port, so it is always 0 for projects created here.
* Which of `verified` / `verified_aux` a loaded card disc has is the loader's business; the writer only requires them for CUE discs (kind 1).
* The original shows `Disco N: <name>` in failure messages using the record name (0x20 bytes) of the disc being written.
