# Porting conventions

This repository is a native macOS (Apple Silicon) port of PicoStation Multi House V3
Manager, originally a Win32 x64 program (mingw C) by ALBERONISSE. The port is produced by
reverse engineering the original executable and re-implementing its behaviour.
Goal: the same behaviour, the same on-disk formats, the same UI text, on macOS.

## Layout

    core/include/mh/<mod>.h     public API of a module
    core/src/<mod>/*.c          implementation (portable C11, no Apple frameworks, no UI)
    core/tests/test_<mod>*.c    assert-based tests (run with `make test-<mod>`)
    core/tests/<mod>.deps       optional: module dirs to link, one per line (default: base)
    platform/mac/               Objective-C/C code that needs Apple frameworks (disk access, images)
    app/                        AppKit user interface
    resources/embedded/         blobs carved from the original executable (see docs/EMBEDDED_DATA.md)
    docs/map/<mod>.md           original function -> port function table, notes, deviations

## Rules for core code

1. C11, `-Wall -Wextra` clean, prefix every public symbol with `mh_` (types `Mh...`).
2. Text is UTF-8 `char *`. The original used UTF-16 `WCHAR`. Where the original capped a
   buffer (for example 260 or 1024 wide chars), keep an equivalent cap in bytes where the cap
   is observable (file formats, limits that produce errors).
3. On-disk and wire formats: explicit little-endian read/write helpers. Never overlay packed
   structs on file bytes. Reproduce offsets, sizes, magic values and CRC/SHA coverage exactly.
4. Reproduce validation rules, limits and error texts exactly (the Portuguese messages in
   the original are ASCII without accents; keep them byte for byte, they are shown in the UI).
   Original code that wrote a message into a caller buffer (`w_copy(buf, n, L"...")`)
   becomes `char *err, size_t err_size` (or a `MhErr` struct, see base.h).
5. No Win32, no `pump_messages`. Long operations take an optional `MhProgress *`
   (callback plus atomic cancel flag) declared in `mh/base.h`; where the original pumped the
   message loop, call `mh_progress_yield()`.
6. 64-bit offsets everywhere (`uint64_t`). Raw device access is in 512-byte blocks; keep the
   original block size, retry and verify-after-write behaviour.
7. No global mutable state unless the original truly was global and it is unavoidable;
   prefer an explicit context struct passed by pointer.
8. Memory: use `malloc/calloc/realloc/free` (the original `p_*` wrappers were HeapAlloc).
9. Every ported function carries a short comment `/* orig: name @0xVA */`. Document deviations
   in `docs/map/<mod>.md`. Do not paste decompiler output into the repository.
10. NEVER write the em dash character (U+2014) anywhere (code, comments, docs, commits).
    `make lint-dash` checks it. Use commas, colons, parentheses or periods.
11. Comments are sparse: say why, not what.

## Reverse engineering workspace (not part of the repository)

The decompiler output is kept outside the repo, in the session scratchpad:

    RE=/private/tmp/claude-501/-Volumes-Renato-PicoStation-BR/cdfb4acc-884d-4bb8-b7b1-d9c0a797961e/scratchpad
    $RE/out/fn/<function>.c     Ghidra decompilation, one file per function (name = symbol)
    $RE/out/all.c               everything concatenated
    $RE/out/callgraph.tsv       VA, name, size, callees
    $RE/out/symbols.tsv         named symbols with section
    $RE/out/defstrings.tsv      every string literal Ghidra found (VA, type, text)
    $RE/exe/mh64.exe            the original executable

Reading hints:

* The program is mingw-w64 C. Symbols were not stripped, so function names are the author's.
* Ghidra shows globals as `DAT_140xxxxxx`. `g` (0x8da40 bytes at 0x140e7b380) is the big
  application state struct; fields are accessed as raw offsets. Rebuild proper structs.
* Functions with big stack frames call `FUN_140001000` (chkstk) and Ghidra then prints
  confusing `register0x00000020 + lVar8` stack offsets. Treat `lVar8` as the frame pointer
  adjustment and recover locals from the access pattern.
* Image file offsets: `.text` VA 0x140001000 = file 0x400, `.data` VA 0x140040000 = file
  0x3F000, `.rdata` VA 0x140f09000 = file 0xF0F000. Use `xxd -s` on `mh64.exe` for raw data.
* x64 Windows calling convention is irrelevant for the port, only semantics matter.
* To confirm a decompiled expression, disassemble: `objdump -d --start-address=0x... --stop-address=0x... mh64.exe`
  (Apple objdump understands PE).
* The program has no source available; treat the decompiled code as the specification.

## Testing

* `make test-<mod>` builds with ASan/UBSan. Write tests that fail if the port is wrong:
  known-answer vectors, round trips (build then validate then load), property checks.
* Real fixtures live in `/Volumes/Renato/PicoStation BR` (CUE/BIN library, `.art` files generated by the
  original) and `/Users/renato.pereira/Downloads/PICOSTATION BR` (original `database/art`, firmware).
  Tests must skip, not fail, when fixtures are absent.
* Never write to a block device in tests. Use regular files as stand-ins.
